# 成本与商业模式

> 基线估算来自 prompt §11.2；`/app/cost` 的计量回填在文末（目前是 Mock 估算，配 Key 后换成实测）。
> 单价以 `config/pricing.ts` 为准（阿里云百炼 2026-11 原价，上线前请到控制台核对）。每次模型调用都会写一条 `usage_log`（model、tokens、cost_cny、feature），下面的估算最终会被真实数据替换。

## 0. 单价表（计算依据）

| 模型 / 服务 | 单价 | 备注 |
|---|---|---|
| qwen3.7-plus（纪要抽取） | 输入 2 元 / 输出 8 元（每百万 tokens） | 质量优先，一场会只调一次 |
| qwen-plus（问答 / 简报） | 输入 0.8 元 / 输出 2 元（每百万 tokens） | 成本优先 |
| text-embedding-v4（建索引 / 重复检测） | ≈ 0.5 元 / 百万 tokens | 不调 LLM，只做向量 |
| Paraformer 录音识别（ASR，可选） | 0.00008 元 / 秒 | ≈ 0.29 元 / 小时；百炼 paraformer-v2 模型页华北2 原价（2026-11-21 复核） |

任务增删改、DDL 计算、提醒调度、风险灯、催办模板全是确定性代码，**边际成本为 0**，不进成本表。

## 1. 单次服务成本（按 1 小时会议估算）

| 项目 | 用量假设 | 计算过程（单价 × 用量） | 成本（元） |
|---|---|---|---|
| 抽取（qwen3.7-plus） | 输入 16k（转写 12k + 历史上下文 2.5k + 提示词 1.5k），输出 2.5k | 16k ÷ 1M × 2 = 0.032；2.5k ÷ 1M × 8 = 0.020 | 0.032 + 0.020 = **0.052** |
| 建索引（text-embedding-v4） | 记忆条目 + 原文分块共 16k tokens | 16k ÷ 1M × 0.5 = 0.008 | ≈ **0.008** |
| 会前简报（qwen-plus） | 输入 4k，输出 0.8k | 4k ÷ 1M × 0.8 = 0.0032；0.8k ÷ 1M × 2 = 0.0016 | **0.0048** |
| **小计（粘贴文字稿 / 钉钉导入）** | | 0.052 + 0.008 + 0.0048 = 0.0648 | **≈ 0.065** |
| ASR（可选，Paraformer） | 3600 秒录音 | 3600 × 0.00008 = 0.288 | ≈ **0.29** |
| **小计（上传录音）** | | 0.0648 + 0.288 = 0.3528 | **≈ 0.35** |
| 实时转写（会议室，可选） | 3600 秒 | 3600 × 0.00024 = 0.864（paraformer-realtime-v2 原价；会议室实际用的 qwen3-asr-flash 单价待核对） | ≈ **0.86** |
| **小计（会议室实时转写）** | | 0.0648 + 0.864 = 0.9288 | **≈ 0.93** |
| 单次问答（qwen-plus） | 输入 3k（问题 + top 8 检索结果），输出 0.4k | 3k ÷ 1M × 0.8 = 0.0024；0.4k ÷ 1M × 2 = 0.0008 | **0.0032** |

一句话：**粘贴文字稿或钉钉导入开一次会约 6 分 5，上传录音约 3 毛 5，会议室实时转写约 9 毛 3，问一次「上次定了啥」3 厘钱。** 贵的不是 AI，是录音转写——所以免费版只开文字稿和钉钉导入（不产生转写费），录音放进付费档。

## 2. 单用户学期成本

假设一个组长一学期：3 门课 × 每门 8 次会 = **24 次会议**，全组累计 **200 次问答**。

| 项目 | 计算过程 | 成本（元） |
|---|---|---|
| 24 次会议（纯文字稿） | 24 × 0.0648 = 1.5552 | ≈ 1.56 |
| 200 次问答 | 200 × 0.0032 = 0.64 | 0.64 |
| **纯文字稿合计（模型成本）** | 1.5552 + 0.64 = 2.1952 | **≈ 2.2** |
| 全部改用录音文件识别（追加） | 24 × 0.288 = 6.912 | 再加 ≈ 6.9 |
| 全部走会议室实时转写（追加） | 24 × 0.864 = 20.736 | 再加 ≈ 20.7 |
| 服务器 / 数据库 / 推送摊销 | 按轻量单机 + SQLite 估 | ≈ 2 |

也就是说：加上摊销，最省的用户一学期花我们约 4.2 元（2.1952 + 2），全用录音文件识别约 11.1 元，全走实时转写约 24.9 元。所以实时转写不能不限量，放进 Pro 的 10 小时额度。

## 3. 定价

| 档位 | 价格 | 包含 | 定位 |
|---|---|---|---|
| 免费版 | 0 元 | 每月 4 次纪要、粘贴文字稿或钉钉导入、1 门课 | 获客：让组长先爽一次 |
| **组长 Pro** | **19.9 元 / 学期** | 3 门课不限次纪要、10 小时录音转写、风险提醒、会前简报 | 主力付费档 |
| 课程版（B 端） | **5 元 / 学生 / 学期** | 老师获得各组贡献度看板（谁按时完成了什么、谁从没更新过） | 规模化收入 |

**组长 Pro 毛利核算**：成本 = 文字稿与问答 2.1952 + 10 小时录音 36000 × 0.00008 = 2.88 + 摊销 2 = **7.0752 元**；毛利 = (19.9 − 7.0752) ÷ 19.9 ≈ **64.4%**。如果 10 小时全走会议室实时转写（0.00024 元/秒）：录音 8.64 元，成本 12.8352 元，毛利 **35.5%**。

**课程版核算**：60 人的课 = 60 × 5 = **300 元**收入，按 12 组算，口径和 Pro 一致：每组 8 次会（文字处理 + 1 小时录音文件识别）+ 200 ÷ 3 次问答 + 摊销 2 ÷ 3 元 = 3.7024 元，12 组 **44.43 元**，毛利 **85.2%**；录音全走实时转写则 99.72 元，毛利 66.8%。一单就是一整个班。

## 3.5 单位经济、敏感度与盈亏平衡（2026-11-21）

上面的 Pro 毛利只算了「这个组自己」。真实的账还要算两件事：它带来的免费用户也在花模型钱；固定成本不该按组摊，而要按月单列，看多少付费组能盖住它。计算代码在 `lib/unit-economics.ts`（单测覆盖），成本看板上有同一张表和一个可调参数的计算器。

**基线假设（除单价外都是假设 · 待验证）**：
- 每组每学期 24 次 × 1 小时会、200 次问答、10 小时录音会后上传、走录音文件识别（0.00008 元/秒；纪要页的「上传音频」目前是 Demo 模拟）；
- Pro 19.9 元 / 学期，支付通道费 0.6%；
- 免费用户 : 付费组 = 4 : 1（20% 付费），免费版每月 4 次纪要、只用文字稿，一学期按 4 个月；
- 固定成本（服务器、数据库、域名）100 元 / 月，即 400 元 / 学期。

**基线结果**：
- 每组变动成本 = 2.1952 + 2.88 = **5.0752 元**；
- 每个免费用户每学期 = 4 × 4 × 0.0648 = **1.0368 元**；
- 净收入 = 19.9 × 0.994 = **19.7806 元**；
- 每组边际贡献 = 19.7806 − 5.0752 − 4 × 1.0368 = **10.5582 元**，单组贡献率 **53.4%**；
- 盈亏平衡 = 400 ÷ 10.5582 ≈ 37.9 → **38 个付费组**；
- 整体毛利（含固定成本）：200 组时 43.3%，500 组时 49.3%。

**敏感度（一次只动一个假设）**：

| 假设 | 取值 | 每组变动成本 | 每组边际贡献 | 单组贡献率 | 盈亏平衡 |
|---|---|---|---|---|---|
| 每次会时长 | 0.5 小时 | 4.4512 | 12.8462 | 64.9% | 32 组 |
| | 1 小时（基线） | 5.0752 | 10.5582 | 53.4% | 38 组 |
| | 2 小时 | 6.3232 | 5.9822 | 30.2% | 67 组 |
| 每组每学期问答 | 100 次 | 4.7552 | 10.8782 | 55.0% | 37 组 |
| | 400 次 | 5.7152 | 9.9182 | 50.1% | 41 组 |
| 录音转写 | 0 小时（只导入文字稿 / 钉钉闪记） | 2.1952 | 13.4382 | 67.9% | 30 组 |
| | 10 小时 · 会议室实时转写（0.00024 元/秒） | 10.8352 | 4.7982 | 24.3% | 84 组 |
| 免费用户 : 付费组 | 0 : 1 | 5.0752 | 14.7054 | 74.3% | 28 组 |
| | 9 : 1（10% 付费） | 5.0752 | 5.3742 | 27.2% | 75 组 |
| Pro 定价 | 9.9 元 | 5.0752 | 0.6182 | 6.3% | 648 组 |
| | 29.9 元 | 5.0752 | 20.4982 | 69.0% | 20 组 |
| 固定成本 | 50 元 / 月 | 5.0752 | 10.5582 | 53.4% | 19 组 |
| | 300 元 / 月 | 5.0752 | 10.5582 | 53.4% | 114 组 |

**怎么读**：
- 最敏感的是三件事：录音走不走实时转写、免费用户比例、定价。会议时长影响中等（2 小时 → 67 组），问答次数影响小（37–41 组）。
- 如果 10 小时全走会议室实时转写：每组贡献 4.80 元，84 组回本，200 / 500 组整体毛利 14.1% / 20.2%。
- 实时转写叠加 10% 付费率：每组贡献 −0.39 元，永远回不了本。
- 贡献为零的价格是 9.28 元，9.9 元基本不赚钱（648 组才回本），所以不往低价走；19.9 元是候选价，待访谈验证。
- 所以实时转写要限量，默认入口是导入文字稿或钉钉闪记，免费版不开录音。额度控制目前是定价方案，代码里还没做。

## 4. 谁使用，谁付钱？

**使用者**分三类：组长（核心用户，每天打开）、组员（被动使用：收提醒、改状态、填一句进度）、老师（B 端看板）。

**付钱的人分两个阶段：**

- **早期是组长。** 理由很直接：痛点最痛（纪要、旧决议、追 DDL 全压在他一个人身上）、决策链最短（自己掏 19.9 不用找任何人审批）、价格锚点合适——19.9 元低于「一杯奶茶 + 一次组会的崩溃」。组员不用付钱，被组长拉进来用就行，这正好降低传播阻力。
- **规模化后是老师 / 学院。** 老师的真实需求不是纪要，是**过程性评价证据**：谁按时完成了什么、谁从头到尾没更新过，用来解决搭便车和互评不公。预算来自教学改革或课程建设经费，5 元 / 学生 / 学期对这个口子来说几乎是零头。

**增长路径（自下而上）**：组长免费试用 → 觉得好用带动全组组员使用 → 老师看到贡献度看板 → 课程整体采购。每一环的推动者都是上一环的受益者，不需要销售地推。

## 5. 待验证的关键假设

这三条没验证之前，上面的账都只是纸面推演（访谈计划见 `docs/research/interview-targets.md`）：

1. **组长付费意愿**：19.9 元 / 学期，组长真的愿意自己掏吗？还是「痛但忍」？免费版每月 4 次够不够形成依赖？
2. **老师为贡献度数据付费的意愿**：老师是否认「过程性证据」这个价值？采购走个人课题经费还是学院统一预算？决策周期多长？
3. **组员对被追踪的接受度**：贡献度看板会不会让组员抵触、故意少在工具里留痕？如果组员不配合改状态，数据失真，B 端价值就塌了。

## Mock 估算回填（2026-11-20，MOCK_LLM=true，未调用真实模型）

数据源：`usage_log`（`/app/cost`）。`npm run seed` 生成 6 场历史会议的计量，再加 1 场现场处理的示例新会议；问答、简报各 3 次是种子真的跑出来的。Mock 不调模型，每条记录 = **流水线真实会发出的 prompt** + Mock 输出，按字数估算 tokens（1 个汉字 ≈ 1 token，比 Qwen 实际分词略多约 10%）。

> 2026-11-20 更正：此前这里写的「实测」里，问答（3000/400 tokens）和简报（4000/800 tokens）是种子按基线假设直接写进 `usage_log` 的，抽取也额外加了 4000 tokens，等于把假设读回来当实测。已删除，下表为按真实 prompt 重新估算的结果。

| 指标 | 估算基线（元） | Mock 估算（元） | 说明 |
|---|---|---|---|
| 单次会议（1200–1800 字转写，粘贴文字稿） | — | ≈ 0.0055（召回 0.0001 + 抽取 0.0047 + 建索引 0.0008） | 抽取 prompt 约 1.7k tokens、输出约 150 tokens |
| 单次会议（按 1 小时 12k tokens 转写） | ≈ 0.065 | 按转写长度线性放大，仍用基线 | 演示转写只有真实会议的 1/8 左右 |
| 单次问答 | ≈ 0.0032（输入 3k） | ≈ 0.0004（输入约 330、输出约 50 tokens） | top 8 记忆条目都是短句，实际 prompt 远小于 3k |
| 会前简报 | ≈ 0.0048（输入 4k） | ≈ 0.0002（输入约 130、输出约 60 tokens） | 简报素材是结构化清单，不是整段转写 |

**怎么读这张表：** 抽取成本跟转写长度成正比，演示会议短，所以便宜；真实 1 小时会议仍按基线 ≈ 0.065 元报价。问答和简报的真实 prompt 比基线假设小一个数量级，说明基线是偏保守的上限。**定价与毛利继续用上文基线口径；配上百炼 Key 后，`/app/cost` 记录的是接口返回的真实 usage，可直接替换本表。**
