# 成本与商业模式

> 基线估算来自 prompt §11.2，作为报价的假设上限；2026-11-21 用真实百炼接口实测过一遍，见文末「实测回填」和 `docs/real-run-report.md`。
> **2026-11-22 修订：计价单位改成「一门课的一支小组」。** 不同课的小组成员可以不一样（同一个人可以在 A 课当组长、在 B 课当组员），把一个组长的三门课当成「一个组」既对不上付钱的人，也把单组用量放大了 3 倍。第 3、3.5、3.6、4、5 节已按新口径重算；第 2 节保留为「一个组长带三个组」的用量，用于多组包。
> 单价以 `config/pricing.ts` 为准（阿里云百炼 2026-11 原价，上线前请到控制台核对）。每次模型调用都会写一条 `usage_log`（model、tokens、cost_cny、feature）。

## 1. 单次服务成本（按 1 小时会议估算）

| 项目 | 用量假设 | 计算过程（单价 × 用量） | 成本（元） |
|---|---|---|---|
| 抽取（qwen3.7-plus） | 输入 16k（转写 12k + 历史上下文 2.5k + 提示词 1.5k），输出 2.5k | 16k ÷ 1M × 2 = 0.032；2.5k ÷ 1M × 8 = 0.020 | 0.032 + 0.020 = **0.052** |
| 建索引（text-embedding-v4） | 记忆条目 + 原文分块共 16k tokens | 16k ÷ 1M × 0.5 = 0.008 | ≈ **0.008** |
| 会前简报（qwen-plus） | 输入 4k，输出 0.8k | 4k ÷ 1M × 0.8 = 0.0032；0.8k ÷ 1M × 2 = 0.0016 | **0.0048** |
| **小计（粘贴文字稿 / 钉钉导入）** | | 0.052 + 0.008 + 0.0048 = 0.0648 | **≈ 0.065** |
| ASR（可选，Paraformer） | 3600 秒录音 | 3600 × 0.00008 = 0.288 | ≈ **0.29** |
| **小计（上传录音）** | | 0.0648 + 0.288 = 0.3528 | **≈ 0.35** |
| 实时转写（会议室，可选） | 3600 秒 | 3600 × 0.00022 = 0.792（qwen3-asr-flash，官方文档 + 控制台 2026-11-21 核实；输出不计费） | ≈ **0.79** |
| **小计（会议室实时转写）** | | 0.0648 + 0.792 = 0.8568 | **≈ 0.86** |
| 单次问答（qwen-plus） | 输入 3k（问题 + top 8 检索结果），输出 0.4k | 3k ÷ 1M × 0.8 = 0.0024；0.4k ÷ 1M × 2 = 0.0008 | **0.0032** |

一句话：**粘贴文字稿或钉钉导入开一次会约 6 分 5，上传录音约 3 毛 5，会议室实时转写约 8 毛 6，问一次「上次定了啥」3 厘钱。** 贵的不是 AI，是录音转写——所以体验版只开文字稿和钉钉导入（不产生转写费），录音放进付费档。

## 2. 一个组长带三个组的学期用量（多组包口径）

假设一个组长一学期带 3 个组（3 门课 × 每门 8 次会）= **24 次会议**，三个组累计 **200 次问答**。一支小组（一门课）就是其中的 1/3：8 次会、约 67 次问答。

| 项目 | 计算过程 | 成本（元） |
|---|---|---|
| 24 次会议（纯文字稿） | 24 × 0.0648 = 1.5552 | ≈ 1.56 |
| 200 次问答 | 200 × 0.0032 = 0.64 | 0.64 |
| **纯文字稿合计（模型成本）** | 1.5552 + 0.64 = 2.1952 | **≈ 2.2** |
| 全部改用录音文件识别（追加） | 24 × 0.288 = 6.912 | 再加 ≈ 6.9 |
| 全部走会议室实时转写（追加） | 24 × 0.792 = 19.008 | 再加 ≈ 19.0 |
| 服务器 / 数据库 / 推送摊销 | 按轻量单机 + SQLite 估 | ≈ 2 |

也就是说：加上摊销，最省的用户一学期花我们约 4.2 元（2.1952 + 2），全用录音文件识别约 11.1 元，全走实时转写约 23.2 元（4.1952 + 19.008），已经超过多组包 19.9 元的定价。所以实时转写不能不限量，单组专业版只含 3 小时录音。

## 3. 定价

| 档位 | 价格 | 包含 | 定位 |
|---|---|---|---|
| 体验版 | 0 元 | 1 个小组、**每学期 3 次纪要**、粘贴文字稿或钉钉导入、不开录音 | 获客：让小组先用起来 |
| **专业版** | **9.9 元 / 组 / 学期** | 一门课的一支小组：不限次纪要、**3 小时录音转写**、任务与回顾、提醒、会前简报；组里任何人买、全组用，可 AA（5 人每人约 1.98 元） | 主力付费档（C 端） |
| 多组包 | **19.9 元 / 人 / 学期** | 你当组长的全部小组一起升级（最多 4 个），每组 3 小时录音 | 同时带几门课的组长 |
| 团体购入版 | **每人每门课：30–99 人 5 元、100–499 人 4 元、500 人以上 3 元** | 老师给一门课的学生统一开通，每个小组都有专业版功能；管理者看各组过程数据（规划中，Demo 未实现） | 规模化收入（ToB） |

**为什么按「一门课的一支小组」计价**：
- 组员按课不同：林晓在三门课里可能是三支不同的队伍，付钱的人、拍板的人都按组走。同一个人可以在 A 课当组长、在 B 课只是组员，按「组长这个人」卖订阅不自然；带多个组的组长另有多组包。
- 用量按组算：一支小组一学期约 8 次会，用量只有原「三门课一组」口径的 1/3，所以单组价从 19.9 降到 9.9。旧文档里「9.9 元基本不赚钱（648 组回本）」是按三门课的用量算的，换成单组用量后 9.9 元每组贡献 7.47 元。
- 体验版额度必须小于一支小组的用量：旧方案「每月 4 次」= 一学期约 16 次，比一支小组一学期开的会还多，单门课的小组永远不需要付费；沿用的话每组贡献降到 4.10 元、98 组才回本。所以改成每学期 3 次。
- **付钱的人和拍板的人分开**：付款人只决定「用不用」，确认决定、审批延期的仍是这个组的组长（Demo 里付款流程还没做）。

**专业版（单组）毛利核算**（每组每学期）：成本 = 文字处理 8 × 0.0648 + 问答 67 × 0.0032 = 0.7328 + 3 小时录音 10800 × 0.00008 = 0.864 + 摊销 2/3 ≈ 0.6667 = **2.2635 元**；毛利 = (9.9 − 2.2635) ÷ 9.9 ≈ **77.1%**。3 小时全走会议室实时转写（0.00022 元/秒）：录音 2.376 元，成本 3.7755 元，毛利 **61.9%**。

**多组包毛利核算**（按带 3 个组）：成本 = 2.1952 + 9 小时录音 2.592 + 摊销 2 = **6.7872 元**，毛利 **65.9%**；全走实时转写成本 11.3232 元，毛利 43.1%。顶格带 4 个组时成本约 9.05 元（24 → 32 次会、录音 12 小时、摊销 8/3 元），毛利约 54.5%，每包贡献约 10.29 元、39 个包回本，所以「最多 4 个」是上限，不能再放宽。

**团体购入版核算**（每组 5 人、8 次会〔文字处理 + 每次 1 小时录音〕+ 200 ÷ 3 次问答 + 摊销 2/3 元，每组 3.7024 元）：定价单位是「每人每门课」，所以每人成本 = 3.7024 ÷ 5 = 0.7405 元（实时转写 7.7344 ÷ 5 = 1.5469 元）：

| 每人每门课 | 适用人数 | 毛利：录音文件识别 | 毛利：会议室实时转写 |
|---|---|---|---|
| 5 元 | 30–99 人 | 85.2% | 69.1% |
| 4 元 | 100–499 人 | 81.5% | 61.3% |
| 3 元 | 500 人以上 | 75.3% | 48.4% |

**学校按人包下全部课程时要另算**：一个学生在 k 门课里各有一个小组，每人成本 = k × 每组成本 ÷ 每组人数。k = 3 时每人 2.2214 元（录音文件识别），按 5 / 4 / 3 元收毛利 55.6% / 44.5% / 26.0%；实时转写每人 4.6406 元，4 元和 3 元档都亏。所以全校包要按人均课程数定价，并且只开会后上传录音。例（按一门课算，k = 1）：一门 60 人的课 = 300 元，成本 44.43 元（录音文件识别）或 92.81 元（实时转写）。阶梯价是假设 · 待验证。

## 3.5 单位经济、敏感度与盈亏平衡（2026-11-22 按单组重算）

上面的毛利只算了「这个组自己」。真实的账还要算两件事：体验版小组也在花模型钱；固定成本按月单列，看多少付费组能盖住它。计算代码在 `lib/unit-economics.ts`（单测覆盖），成本看板上有同一张表和可调参数的计算器。

**基线假设（除单价外都是假设 · 待验证）**：
- 一支小组每学期 8 次 × 1 小时会、约 67 次问答、3 小时录音会后上传、走录音文件识别（0.00008 元/秒）；
- 专业版 9.9 元 / 组 / 学期，支付通道费 0.6%；
- 体验版小组 : 付费组 = 4 : 1（20% 付费），体验版每学期 3 次纪要、只用文字稿；
- 固定成本（服务器、数据库、域名）100 元 / 月，即 400 元 / 学期。

**基线结果**：
- 每组变动成本 = 0.7328 + 0.864 = **1.5968 元**；
- 每个体验版小组每学期 = 3 × 0.0648 = **0.1944 元**；
- 净收入 = 9.9 × 0.994 = **9.8406 元**；
- 每组边际贡献 = 9.8406 − 1.5968 − 4 × 0.1944 = **7.4662 元**，单组贡献率 **75.9%**；
- 盈亏平衡 = 400 ÷ 7.4662 ≈ 53.6 → **54 个付费组**；
- 整体毛利（含固定成本）：200 组时 55.5%，500 组时 67.7%；
- 多组包（19.9 元，带 3 个组，配 3 × 4 = 12 个体验版小组）：每包贡献 12.6606 元，**32 个付费包**回本。

**敏感度（一次只动一个假设）**：

| 假设 | 取值 | 每组变动成本 | 每组边际贡献 | 单组贡献率 | 盈亏平衡 |
|---|---|---|---|---|---|
| 每次会时长 | 0.5 小时 | 1.3888 | 7.9862 | 81.2% | 51 组 |
| | 1 小时（基线） | 1.5968 | 7.4662 | 75.9% | 54 组 |
| | 2 小时 | 2.0128 | 6.4262 | 65.3% | 63 组 |
| 每组每学期会议 | 4 次 | 1.3376 | 7.7254 | 78.5% | 52 组 |
| | 16 次 | 2.1152 | 6.9478 | 70.6% | 58 组 |
| 录音转写 | 0 小时（只导入文字稿 / 钉钉闪记） | 0.7328 | 8.3302 | 84.7% | 49 组 |
| | 3 小时 · 会议室实时转写 | 3.1088 | 5.9542 | 60.5% | 68 组 |
| | 8 小时 · 每次会都实时转写 | 7.0688 | 1.9942 | 20.3% | 201 组 |
| 体验版小组 : 付费组 | 0 : 1 | 1.5968 | 8.2438 | 83.8% | 49 组 |
| | 9 : 1（10% 付费） | 1.5968 | 6.4942 | 66.0% | 62 组 |
| 体验版额度 | 每月 4 次（旧方案，约 16 次 / 学期） | 1.5968 | 4.0966 | 41.6% | 98 组 |
| 专业版定价 | 6.9 元 | 1.5968 | 4.4842 | 65.4% | 90 组 |
| | 12.9 元 | 1.5968 | 10.4482 | 81.5% | 39 组 |
| 固定成本 | 50 元 / 月 | 1.5968 | 7.4662 | 75.9% | 27 组 |
| | 300 元 / 月 | 1.5968 | 7.4662 | 75.9% | 161 组 |

**怎么读**：
- 最敏感的是：每次会都走实时转写（201 组）、体验版额度（98 组）、固定成本（161 组）。会议时长、次数、付费率影响中等（51–63 组）。
- 3 小时全走会议室实时转写：每组贡献 5.95 元，68 组回本，200 / 500 组整体毛利 40.2% / 52.4%；再叠加 10% 付费率：每组贡献 4.98 元，81 组回本。
- 贡献为零的价格约 2.39 元，9.9 元离它很远；12.9 元能把回本压到 39 组，但对单门课的小组偏贵。9.9 元是候选价，待访谈验证。
- 所以实时转写要限量（单组 3 小时），默认入口是导入文字稿或钉钉闪记，体验版不开录音。额度控制目前是定价方案，代码里还没做。

## 3.6 线下开会分清「谁说的」：方案与成本（规划，Demo 未实现）

**现状**：粘贴腾讯会议 / 飞书导出、钉钉会议导入时，发言人来自各自的账号，本来就分得清。分不清的只有会议室麦克风：一台设备录到的是混在一起的声音，qwen3-asr-flash 只返回文字、不返回说话人，现在只能由组长手动选「当前发言人」。原本想直接接钉钉 AI 听记，但它没有公开接口（见 `docs/dingtalk-integration.md`）。

**方案**：散会后把整段录音交给百炼 paraformer-v2 录音文件识别，打开说话人分离（`diarization_enabled`，可用 `speaker_count` 提示人数），每句话带 `speaker_id`，也就是「说话人 0 / 1 / 2」。确认页里给每个编号放一句原话，由拍板的人点选对应组员，一场会做一次；对上之后，「我来做」就能归到具体的人。限制：只支持单声道、建议不超过 2 小时；接口要的是文件链接，需要先把录音存到对象存储；抢话或声音相近时会分错，所以结果仍要组长确认。

**成本**（录音文件识别 0.00008 元 / 秒，1 小时 0.288 元）：

| 做法 | 每小时转写成本 | 专业版单组（3 小时 / 组 / 学期）毛利 | 单位经济：每组贡献 / 回本 | 团体购入每人每门课成本，5 / 4 / 3 元档毛利 |
|---|---|---|---|---|
| 只做会后分离，不要实时字幕 | 0.288 元 | 77.1%（和基线相同） | 7.47 元 / 54 组 | 0.7405 元：85.2% / 81.5% / 75.3% |
| 实时字幕 + 会后分离 | 0.792 + 0.288 = 1.08 元 | 每组成本 0.7328 + 3.24 + 0.6667 = 4.6395 元，毛利 53.1% | 5.09 元 / 79 组 | 2.0077 元（团体购入口径：每组 8 次会、每次 1 小时录音）：59.8% / 49.8% / 33.1% |

**取舍**：线下会默认「会后分离」，分清发言人不额外加钱，代价是开会时看不到实时文字和「这事定过了」的提醒；实时字幕作为专业版里限量的加值项。两者叠加会把回本推到 79 组，不能默认全开。

## 4. 谁使用，谁付钱？

**使用者**分三类：组长（核心用户，确认决定、只看待我处理）、组员（认领任务、一键回复进度）、老师 / 机构管理者（看各组过程数据，规划中）。

**付钱的人：**

- **C 端（专业版，单组）：这支小组里的任何一个人，或者 AA。** 第一个客户是组长：痛点最痛、决策链最短。但计价单位是一门课的一支小组，实际买单的往往是组里最受不了混乱的那个人，不一定是组长；也可以 AA，5 人每人约 1.98 元。一个学生在三门课里有三支不同的小组时，每支组各自决定买不买。付钱的人和拍板的人分开，确认决定的仍是这个组的组长。
- **C 端（多组包）：同时带几个组的组长本人。** 19.9 元把 TA 当组长的全部小组一起升级，比每组单买（3 × 9.9 = 29.7 元）便宜。
- **B 端（团体购入版）：老师、学院、社团等机构。** 他们买的是统一开通和各组的过程性证据（谁按时完成了什么、谁从没更新过），用来解决搭便车和互评不公；预算来自教学改革、课程建设或社团经费。按人数阶梯每人每门课 5 / 4 / 3 元；学校按人包下全部课程要按人均课程数另算（见第 3 节）。

**增长路径（自下而上）**：小组用体验版试用 → 有人买专业版或 AA，全组用起来 → 老师或社团负责人看到各组都在用 → 机构团体购入。每一环的推动者都是上一环的受益者。

## 5. 待验证的关键假设

这三条没验证之前，上面的账都只是纸面推演（访谈计划见 `docs/research/interview-targets.md`）：

1. **小组付费意愿**：9.9 元 / 组 / 学期，组长或某个组员愿意掏吗？AA 会不会更容易成交？体验版每学期 3 次够不够形成依赖？带多个组的组长会不会买 19.9 元的多组包？
2. **机构为过程数据付费的意愿**：老师、学院、社团是否认「过程性证据」这个价值？采购走课题经费还是统一预算？阶梯价 5 / 4 / 3 元能不能谈下来？决策周期多长？
3. **组员对被追踪的接受度**：贡献度看板会不会让组员抵触、故意少在工具里留痕？如果组员不配合改状态，数据失真，B 端价值就塌了。

## Mock 估算回填（2026-11-20，MOCK_LLM=true，未调用真实模型）

数据源：`usage_log`（`/app/cost`）。`npm run seed` 生成 6 场历史会议的计量，再加 1 场现场处理的示例新会议；问答、简报各 3 次是种子真的跑出来的。Mock 不调模型，每条记录 = **流水线真实会发出的 prompt** + Mock 输出，按字数估算 tokens（1 个汉字 ≈ 1 token，比 Qwen 实际分词略多约 10%）。

> 2026-11-20 更正：此前这里写的「实测」里，问答（3000/400 tokens）和简报（4000/800 tokens）是种子按基线假设直接写进 `usage_log` 的，抽取也额外加了 4000 tokens，等于把假设读回来当实测。已删除，下表为按真实 prompt 重新估算的结果。

| 指标 | 估算基线（元） | Mock 估算（元） | 说明 |
