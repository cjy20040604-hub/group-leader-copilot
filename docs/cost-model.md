# 成本与商业模式

> 基线估算来自 prompt §11.2，作为报价的假设上限；2026-11-21 用真实百炼接口实测过一遍，见文末「实测回填」和 `docs/real-run-report.md`。
> **2026-11-22 修订：计价单位改成「一门课的一支小组」。** 不同课的小组成员可以不一样（同一个人可以在 A 课当组长、在 B 课当组员），把一个组长的三门课当成「一个组」既对不上付钱的人，也把单组用量放大了 3 倍。第 3、3.5、3.6、4、5 节已按新口径重算（同日二次修订：纪要版 6.9 元 / 专业版 14.9 元含 8 小时实时转写 / 加时包 3 小时 3.9 元）；第 2 节保留为「一个组长带三个组」的用量，用于多组包。
> 单价以 `config/pricing.ts` 为准（阿里云百炼 2026-11 原价，上线前请到控制台核对）。每次模型调用都会写一条 `usage_log`（model、tokens、cost_cny、feature）。

## 0. 单价表（计算依据）

| 模型 / 服务 | 单价 | 备注 |
|---|---|---|
| qwen3.7-plus（纪要抽取） | 输入 2 元 / 输出 8 元（每百万 tokens） | 质量优先，一场会只调一次 |
| qwen-plus（问答 / 简报） | 输入 0.8 元 / 输出 2 元（每百万 tokens） | 成本优先 |
| text-embedding-v4（建索引 / 重复检测） | ≈ 0.5 元 / 百万 tokens | 不调 LLM，只做向量 |
| Paraformer 录音识别（ASR，可选） | 0.00008 元 / 秒 | ≈ 0.29 元 / 小时；百炼 paraformer-v2 模型页华北2 原价（2026-11-21 复核） |

任务增删改、DDL 计算、提醒调度、风险灯、催办模板全是确定性代码，**边际成本为 0**，不进成本表。

## 1. 单次服务成本（按 1 小时会议估算）

| 项目 | 用量假设 | 计算过程（单价 × 用量） | 成本（元） |
|---|---|---|---|
| 抽取（qwen3.7-plus） | 输入 16k（转写 12k + 历史上下文 2.5k + 提示词 1.5k），输出 2.5k | 16k ÷ 1M × 2 = 0.032；2.5k ÷ 1M × 8 = 0.020 | 0.032 + 0.020 = **0.052** |
| 建索引（text-embedding-v4） | 记忆条目 + 原文分块共 16k tokens | 16k ÷ 1M × 0.5 = 0.008 | ≈ **0.008** |
| 会前简报（qwen-plus） | 输入 4k，输出 0.8k | 4k ÷ 1M × 0.8 = 0.0032；0.8k ÷ 1M × 2 = 0.0016 | **0.0048** |
| **小计（粘贴文字稿 / 钉钉导入）** | | 0.052 + 0.008 + 0.0048 = 0.0648 | **≈ 0.065** |
| ASR（可选，Paraformer） | 3600 秒录音 | 3600 × 0.00008 = 0.288 | ≈ **0.29** |
| **小计（上传录音）** | | 0.0648 + 0.288 = 0.3528 | **≈ 0.35** |
| 实时转写（会议室，可选） | 3600 秒 | 3600 × 0.00022 = 0.792（qwen3-asr-flash，官方文档 + 控制台 2026-11-21 核实；输出不计费） | ≈ **0.79** |
| **小计（会议室实时转写）** | | 0.0648 + 0.792 = 0.8568 | **≈ 0.86** |
| 单次问答（qwen-plus） | 输入 3k（问题 + top 8 检索结果），输出 0.4k | 3k ÷ 1M × 0.8 = 0.0024；0.4k ÷ 1M × 2 = 0.0008 | **0.0032** |

一句话：**粘贴文字稿或钉钉导入开一次会约 6 分 5，上传录音约 3 毛 5，会议室实时转写约 8 毛 6，问一次「上次定了啥」3 厘钱。** 贵的不是 AI，是录音转写——所以体验版只开文字稿和钉钉导入（不产生转写费），录音放进付费档。

## 2. 一个组长带三个组的学期用量（多组包口径）

假设一个组长一学期带 3 个组（3 门课 × 每门 8 次会）= **24 次会议**，三个组累计 **200 次问答**。一支小组（一门课）就是其中的 1/3：8 次会、约 67 次问答。

| 项目 | 计算过程 | 成本（元） |
|---|---|---|
| 24 次会议（纯文字稿） | 24 × 0.0648 = 1.5552 | ≈ 1.56 |
| 200 次问答 | 200 × 0.0032 = 0.64 | 0.64 |
| **纯文字稿合计（模型成本）** | 1.5552 + 0.64 = 2.1952 | **≈ 2.2** |
| 全部改用录音文件识别（追加） | 24 × 0.288 = 6.912 | 再加 ≈ 6.9 |
| 全部走会议室实时转写（追加） | 24 × 0.792 = 19.008 | 再加 ≈ 19.0 |
| 服务器 / 数据库 / 推送摊销 | 按轻量单机 + SQLite 估 | ≈ 2 |

也就是说：加上摊销，最省的用户一学期花我们约 4.2 元（2.1952 + 2），全用录音文件识别约 11.1 元，全走实时转写约 23.2 元（4.1952 + 19.008），比多组包 14.9 元的定价还高。所以实时转写不能不限量：多组包只含纪要，实时转写放在专业版里（每组 8 小时），超出买加时包。

## 3. 定价（2026-11-22 二次修订：纪要和实时转写分开卖）

| 档位 | 价格 | 包含 | 定位 |
|---|---|---|---|
| 体验版 | 0 元 | 1 个小组、**每学期 3 次纪要**、粘贴文字稿或钉钉导入、不含实时转写 | 获客：让小组先用起来 |
| **纪要版** | **6.9 元 / 组 / 学期** | 一门课的一支小组：**纪要不限次**（粘贴文字稿、钉钉会议导入）、问答、提醒、会前简报、任务与回顾；不含实时转写；组里任何人买、全组用，可 AA（5 人每人约 1.38 元） | 主力付费档：线上开会、本来就有文字稿的组 |
| **专业版** | **14.9 元 / 组 / 学期** | 纪要版全部（纪要不限次）+ **8 小时会议室实时转写**（开会时有字幕和「这事定过了」提示）；AA 每人约 2.98 元 | 在教室面对面开会、要实时转写的组 |
| 加时包 | **3.9 元 / 3 小时** | 实时转写时长，哪个档位都能买 | 专业版用完、或纪要版偶尔要录一场 |
| 多组包 | **14.9 元 / 人 / 学期** | 你当组长的小组都开纪要版（最多 4 个）；某个组要实时转写就单独升专业版或加时 | 同时带几门课的组长 |
| 团体购入版 | **每人每门课：30–99 人 5 元、100–499 人 4 元、500 人以上 3 元** | 老师给一门课的学生统一开通，每个小组都有纪要版功能，录音散会后上传；管理者看各组过程数据（规划中，Demo 未实现） | 规模化收入（ToB） |

**为什么把纪要和实时转写分开卖**（旧方案是「专业版 9.9 元含 3 小时录音」）：
- 大部分小组用腾讯会议、钉钉开会，本来就有文字稿，只需要纪要。让他们为用不上的录音付 9.9 元，贵了；纪要版成本 1.40 元，卖 6.9 元毛利 79.7%。
- 3 小时不现实：一支小组一学期约 8 次会，每次 1 小时，真要现场转写就是 8 小时。实时转写 1 小时 0.792 元，8 小时 6.336 元，同样 8 小时还卖 9.9 元要 201 组才回本，所以专业版定 14.9 元。
- **额度用完会议不中断**：会照常录音，散会后用录音文件识别整理（0.288 元 / 小时，不另收费，只是没有实时字幕和撞车提示）；还要实时转写就买加时包。代码里实时转写额度用完返回 402，会议室页面自动改成只在本机录音（`lib/plans.ts`、`components/live-meeting.tsx`）；散会后上传录音的录音文件识别在 Demo 里是模拟的（`app/api/asr/route.ts` 按 1 小时计费、返回示例转写），没有接 paraformer-v2。

**为什么按「一门课的一支小组」计价**：
- 组员按课不同：林晓在三门课里可能是三支不同的队伍，付钱的人、拍板的人都按组走。同一个人可以在 A 课当组长、在 B 课只是组员，按「组长这个人」卖订阅不自然；带多个组的组长另有多组包。
- 体验版额度必须小于一支小组的用量：旧方案「每月 4 次」= 一学期约 16 次，比一支小组一学期开的会还多，单门课的小组永远不需要付费；沿用的话专业版每组贡献降到 3.59 元、112 组才回本。所以改成每学期 3 次。
- **付钱的人和拍板的人分开**：付款人只决定「用不用」，确认决定、审批延期的仍是这个组的组长（Demo 的设置页能演示开通纪要版 / 专业版、谁付款、AA、加时包和多组包，不接支付、不扣款）。

**纪要版毛利核算**（每组每学期）：成本 = 文字处理 8 × 0.0648 + 问答 67 × 0.0032 = 0.7328 + 摊销 2/3 ≈ 0.6667 = **1.3995 元**；毛利 = (6.9 − 1.3995) ÷ 6.9 ≈ **79.7%**。

**专业版毛利核算**：成本 = 0.7328 + 8 小时实时转写 28800 × 0.00022 = 6.336 + 摊销 0.6667 = **7.7355 元**；毛利 = (14.9 − 7.7355) ÷ 14.9 ≈ **48.1%**。这是 8 小时全部用满的最坏情况；浏览器端只把有人说话的片段送去识别，按实际用 6 小时算毛利 **58.7%**。

**加时包核算**：3 小时实时转写成本 2.376 元，扣 0.6% 通道费后毛利 **38.5%**（按满额用完算）。

**多组包核算**（按带 3 个组，都开纪要版）：成本 = 3 × 0.7328 + 摊销 2 = **4.1952 元**，毛利 **71.8%**；比每组单买纪要版（3 × 6.9 = 20.7 元）便宜。顶格带 4 个组时成本约 5.59 元，毛利约 62.5%，每包贡献约 8.77 元、46 个包回本，所以「最多 4 个」是上限。

**团体购入版核算**（每组 5 人、8 次会〔文字处理 + 每次 1 小时录音〕+ 200 ÷ 3 次问答 + 摊销 2/3 元，每组 3.7024 元）：定价单位是「每人每门课」，所以每人成本 = 3.7024 ÷ 5 = 0.7405 元（实时转写 7.7344 ÷ 5 = 1.5469 元）：

| 每人每门课 | 适用人数 | 毛利：录音文件识别 | 毛利：会议室实时转写 |
|---|---|---|---|
| 5 元 | 30–99 人 | 85.2% | 69.1% |
| 4 元 | 100–499 人 | 81.5% | 61.3% |
| 3 元 | 500 人以上 | 75.3% | 48.4% |

**学校按人包下全部课程时要另算**：一个学生在 k 门课里各有一个小组，每人成本 = k × 每组成本 ÷ 每组人数。k = 3 时每人 2.2214 元（录音文件识别），按 5 / 4 / 3 元收毛利 55.6% / 44.5% / 26.0%；实时转写每人 4.6406 元，4 元和 3 元档都亏。所以全校包要按人均课程数定价，并且只开散会后上传录音。例（按一门课算，k = 1）：一门 60 人的课 = 300 元，成本 44.43 元（录音文件识别）或 92.81 元（实时转写）。阶梯价是假设 · 待验证。

## 3.5 单位经济、敏感度与盈亏平衡（2026-11-22 按纪要版 / 专业版重算）

上面的毛利只算了「这个组自己」。真实的账还要算两件事：体验版小组也在花模型钱；固定成本按月单列，看多少付费组能盖住它。计算代码在 `lib/unit-economics.ts`（单测覆盖），成本看板上有同一张表和可调参数的计算器。

**基线假设（除单价外都是假设 · 待验证）**：
- 一支小组每学期 8 次 × 1 小时会、约 67 次问答；纪要版不含录音，专业版 8 小时全部走会议室实时转写（qwen3-asr-flash 0.00022 元/秒）；
- 纪要版 6.9 元、专业版 14.9 元 / 组 / 学期，支付通道费 0.6%；付费组里 7 成买纪要版、3 成买专业版；
- 体验版小组 : 付费组 = 4 : 1（20% 付费），体验版每学期 3 次纪要、只用文字稿；
- 固定成本（服务器、数据库、域名）100 元 / 月，即 400 元 / 学期。

**基线结果**：
- 每个体验版小组每学期 = 3 × 0.0648 = **0.1944 元**；
- 纪要版：变动成本 **0.7328 元**，净收入 6.9 × 0.994 = 6.8586 元，每组边际贡献 = 6.8586 − 0.7328 − 4 × 0.1944 = **5.3482 元**（贡献率 78.0%），只卖纪要版 400 ÷ 5.3482 ≈ 74.8 → **75 个付费组**回本；
- 专业版：变动成本 0.7328 + 6.336 = **7.0688 元**，净收入 14.8106 元，每组贡献 **6.9642 元**（贡献率 47.0%），只卖专业版 **58 组**回本；实际只用 6 小时时 47 组；
- **7 成纪要版 + 3 成专业版**：加权每组贡献 0.7 × 5.3482 + 0.3 × 6.9642 = **5.8330 元**，**69 个付费组**回本；整体毛利（含固定成本）200 组时 41.5%，500 组时 54.4%；
- 多组包（14.9 元，带 3 个组都开纪要版，配 3 × 4 = 12 个体验版小组）：每包贡献 10.2826 元，**39 个付费包**回本。

**专业版敏感度（一次只动一个假设）**：

| 假设 | 取值 | 每组变动成本 | 每组边际贡献 | 单组贡献率 | 盈亏平衡 |
|---|---|---|---|---|---|
| 每次会时长 | 0.5 小时 | 6.8608 | 7.4842 | 50.5% | 54 组 |
| | 1 小时（基线） | 7.0688 | 6.9642 | 47.0% | 58 组 |
| | 2 小时 | 7.4848 | 5.9242 | 40.0% | 68 组 |
| 每组每学期会议 | 4 次 | 6.8096 | 7.2234 | 48.8% | 56 组 |
| | 16 次 | 7.5872 | 6.4458 | 43.5% | 63 组 |
| 实时转写实际用了多少 | 0 小时（成本和纪要版一样） | 0.7328 | 13.3002 | 89.8% | 31 组 |
| | 6 小时（只算有人说话的部分） | 5.4848 | 8.5482 | 57.7% | 47 组 |
| | 8 小时 + 散会后再转 5 小时录音文件 | 8.5088 | 5.5242 | 37.3% | 73 组 |
| 体验版小组 : 付费组 | 0 : 1 | 7.0688 | 7.7418 | 52.3% | 52 组 |
| | 9 : 1（10% 付费） | 7.0688 | 5.9922 | 40.5% | 67 组 |
| 体验版额度 | 每月 4 次（旧方案，约 16 次 / 学期） | 7.0688 | 3.5946 | 24.3% | 112 组 |
| 专业版定价 | 12.9 元 | 7.0688 | 4.9762 | 38.8% | 81 组 |

**怎么读**：
- 最敏感的是：专业版降到 9.9 元（201 组）、固定成本（173 组）、体验版额度（112 组）。会议时长、次数、付费率影响中等（52–68 组）。
- 纪要版的价格：4.9 元要 120 组、5.9 元 92 组、6.9 元 75 组、7.9 元 64 组；贡献为零的价格约 1.52 元。专业版贡献为零的价格约 7.89 元，14.9 元离它近一倍。6.9 / 14.9 都是候选价，待访谈验证。
- 额度用完散会后整理会多花钱，但很少：8 小时用满后再转 5 小时录音文件，回本从 58 升到 73 组。
- 体验版 3 次纪要、专业版 8 小时实时转写、加时包的额度已经在代码里按规则拦截（`lib/plans.ts`），额度数字和这里的基线是同一份。

## 3.6 线下开会分清「谁说的」：方案与成本（规划，Demo 未实现）

**现状**：粘贴腾讯会议 / 飞书导出、钉钉会议导入时，发言人来自各自的账号，本来就分得清。分不清的只有会议室麦克风：一台设备录到的是混在一起的声音，qwen3-asr-flash 只返回文字、不返回说话人，现在只能由组长手动选「当前发言人」。原本想直接接钉钉 AI 听记，但它没有公开接口（见 `docs/dingtalk-integration.md`）。

**方案**：散会后把整段录音交给百炼 paraformer-v2 录音文件识别，打开说话人分离（`diarization_enabled`，可用 `speaker_count` 提示人数），每句话带 `speaker_id`，也就是「说话人 0 / 1 / 2」。确认页里给每个编号放一句原话，由拍板的人点选对应组员，一场会做一次；对上之后，「我来做」就能归到具体的人。限制：只支持单声道、建议不超过 2 小时；接口要的是文件链接，需要先把录音存到对象存储；抢话或声音相近时会分错，所以结果仍要组长确认。

**成本**（录音文件识别 0.00008 元 / 秒，1 小时 0.288 元）：会后分离就是专业版实时额度用完后的降级路径，每小时 0.288 元，不另收费。

| 做法 | 每小时转写成本 | 按一学期 8 小时算 | 单位经济 |
|---|---|---|---|
| 只做会后分离，不要实时字幕 | 0.288 元 | 转写 2.304 元，每组成本 3.70 元；放进 6.9 元的纪要版毛利只剩 46.3% | 纪要版要 132 组才回本，所以纪要版不含录音 |
| 实时字幕 + 会后分离都开 | 0.792 + 0.288 = 1.08 元 | 转写 8.64 元，专业版成本 10.04 元，毛利 32.6% | 专业版回本 58 → 86 组 |

**取舍**：实时字幕放在专业版里，会后分离只作为额度用完后的兜底。两者默认全开会把回本推到 86 组，不能默认全开。

## 4. 谁使用，谁付钱？

**使用者**分三类：组长（核心用户，确认决定、只看待我处理）、组员（认领任务、一键回复进度）、老师 / 机构管理者（看各组过程数据，规划中）。

**付钱的人：**

- **C 端（纪要版 / 专业版，单组）：这支小组里的任何一个人，或者 AA。** 第一个客户是组长：痛点最痛、决策链最短。但计价单位是一门课的一支小组，实际买单的往往是组里最受不了混乱的那个人，不一定是组长；也可以 AA，纪要版 5 人每人约 1.38 元、专业版约 2.98 元。线上开会有文字稿的组买纪要版，在教室开会要实时转写的组买专业版，不够再加时。一个学生在三门课里有三支不同的小组时，每支组各自决定买不买。付钱的人和拍板的人分开，确认决定的仍是这个组的组长。
- **C 端（多组包）：同时带几个组的组长本人。** 14.9 元让 TA 当组长的小组都开纪要版，比每组单买（3 × 6.9 = 20.7 元）便宜。
- **B 端（团体购入版）：老师、学院、社团等机构。** 他们买的是统一开通和各组的过程性证据（谁按时完成了什么、谁从没更新过），用来解决搭便车和互评不公；预算来自教学改革、课程建设或社团经费。按人数阶梯每人每门课 5 / 4 / 3 元；学校按人包下全部课程要按人均课程数另算（见第 3 节）。

**增长路径（自下而上）**：小组用体验版试用 → 有人买纪要版或 AA，全组用起来；在教室开会的组升专业版 → 老师或社团负责人看到各组都在用 → 机构团体购入。每一环的推动者都是上一环的受益者。

## 5. 待验证的关键假设

这三条没验证之前，上面的账都只是纸面推演（访谈计划见 `docs/research/interview-targets.md`）：

1. **小组付费意愿**：纪要版 6.9 元、专业版 14.9 元 / 组 / 学期，组长或某个组员愿意掏吗？AA 会不会更容易成交？体验版每学期 3 次够不够形成依赖？真有 7 成小组只要纪要吗？实时转写 8 小时够不够、加时包有人买吗？带多个组的组长会不会买 14.9 元的多组包？
2. **机构为过程数据付费的意愿**：老师、学院、社团是否认「过程性证据」这个价值？采购走课题经费还是统一预算？阶梯价 5 / 4 / 3 元能不能谈下来？决策周期多长？
3. **组员对被追踪的接受度**：贡献度看板会不会让组员抵触、故意少在工具里留痕？如果组员不配合改状态，数据失真，B 端价值就塌了。

## Mock 估算回填（2026-11-20，MOCK_LLM=true，未调用真实模型）

数据源：`usage_log`（`/app/cost`）。`npm run seed` 生成 6 场历史会议的计量，再加 1 场现场处理的示例新会议；问答、简报各 3 次是种子真的跑出来的。Mock 不调模型，每条记录 = **流水线真实会发出的 prompt** + Mock 输出，按字数估算 tokens（1 个汉字 ≈ 1 token，比 Qwen 实际分词略多约 10%）。

> 2026-11-20 更正：此前这里写的「实测」里，问答（3000/400 tokens）和简报（4000/800 tokens）是种子按基线假设直接写进 `usage_log` 的，抽取也额外加了 4000 tokens，等于把假设读回来当实测。已删除，下表为按真实 prompt 重新估算的结果。
