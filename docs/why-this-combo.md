# 为什么是这个组合

**一段话（交付用）**

转写和纪要，腾讯会议、钉钉已经能做；真正的对手是「会议软件加一张共享表格」。我们多做的是表格做不到的两件事：一是**跨课撞 DDL 提前提醒**，把几门课的 DDL 放在一起看，同一个组员一周撞两个，首页先提醒组长问一句（一张表格只看得到一门课）；二是**旧决定被推翻就不再当结论**，新决定取代旧的以后，问答和会前简报不再引用旧的（表格里的旧结论会一直留着）。下面的对比表里，前四种组合是为了说明边界，真正要比的是倒数第二行的「听记 + 共享表格」。

组长的三个痛点：散会没人整理、三天后忘了定过什么、DDL 前没人催。它们其实是同一条链断在三个地方：会上说的话 → 确认过的决定 → 有人跟进的任务 → 下次会接着推进。所以我们做的是一条闭环，不是三个单点工具。这条链主要两处需要 AI：一是把口语（语音转写、口语整理成结构）变成结构化的决定和待办，二是按意思回忆旧决议（问问上次、会前简报）。其余环节都用规则：开录、认领、延期审批、提醒、风险灯、带到下次会，因为这些必须可预测、可解释、边际成本几乎为零。AI 产出必须组长确认后才生效。几种看起来更省事的组合，各有一个致命缺口：
- 只做纪要：没人执行；
- 只做任务追踪：组长还得手抄任务；
- 只做 DDL 提醒：提醒的对象从哪来没人管；
- 全交给 Agent：提醒漏发、DDL 算错的代价远大于省下的事，而且长上下文越用越贵；
- 会议软件自带的听记加一张共享表格：听记主要围绕单场会（以当前版本为准），表格要人肉同步，跨会的决定和遗留还是要组长记在脑子里。

所以转写我们不自己卷，当作可替换的入口（粘贴文字稿、会议室录音、钉钉闪记），把价值放在会后：让决定被确认、待办有人跟、三门课的遗留在下次会被接着推进。

## 对比表

| 组合 | 能解决 | 断在哪 | 成本特征 |
|---|---|---|---|
| 只做纪要（转写 → 摘要） | 散会没人整理 | 纪要写完没人执行，下次会也没人翻 | 每场一次模型调用 |
| 只做任务追踪（看板） | 有人跟进 | 组长要手动录任务，录的成本就是原来的痛点 | 几乎为零 |
| 只做 DDL 提醒 | 不漏 DDL | 任务和 DDL 从哪来没人管 | 几乎为零 |
| 全交给 Agent（大模型管纪要、任务、提醒） | 看起来最省事 | 提醒和日期不可预测、不可解释，错一次就失去信任；上下文越积越长，越用越贵 | 随使用线性涨，且不可控 |
| 会议软件听记 + 共享表格（真正的对手） | 单场会纪要、一门课的任务清单 | 听记主要围绕单场会（以当前版本为准）；表格要人同步，一张表只看一门课，看不出同一个人跨课撞 DDL；旧结论被推翻后还留在表里 | 听记的额度和会员权益待核对；表格免费但要人力维护 |
| **本产品：入口可替换 + 窄 AI + 规则执行 + 组长确认** | 三个痛点连成一条链 | 门槛是组员愿不愿意点一下更新（待验证） | AI 主要在整理和回忆两处花钱，执行层边际成本几乎为零 |
